# Протокол клиент ↔ сервер AlyaNovel

Клиент (Kotlin) и сервер (Python/FastAPI) связаны только этим контрактом. Сервер можно менять,
пока контракт сохраняется. Все ответы — JSON в UTF-8, если не сказано иное.

## HTTP API

| Метод и путь | Назначение | Ответ |
|---|---|---|
| `GET /api/{kind}/volumes` (`kind` = `manga` \| `ranobe`) | Тома и главы раздела. Тома без глав не возвращаются | `[{"id","number","title","chapters":[{"id","type","number","title","fmt","size","created"}]}]` — главы уже в порядке пролог → главы → эпилог → экстра |
| `GET /api/chapters/{id}/file` | Файл главы (`.mtx`/`.mpx`), бинарно | `application/octet-stream` |
| `GET /api/latest?since=<unix-сек>` | Главы, созданные позже `since` (для уведомлений) | `[{"id","type","kind","volume","number","title","created"}]` |
| `GET /api/app-version` | Последняя версия приложения | `{"latest":"0.1.0","url":"https://…"}` |
| `POST /api/auth/start` | Начать вход через Telegram | `{"token","url"}` — открыть `url` (бот), опрашивать `poll` |
| `GET /api/auth/poll/{token}` | Опрос входа | `{"status":"pending"}` / `{"status":"ok","session","name"}`; `410` — ссылка устарела (10 минут) |
| `GET /api/chat/messages` | История чата (последние 50), нужен `Authorization: Bearer <session>` | `[{"id","name","text","created"}]`; `401` — сессия недействительна |
| `WS /ws/chat?token=<session>` | Чат в реальном времени | клиент шлёт **простой текст** (до 2000 символов); сервер рассылает JSON `{"id","name","text","created"}`; недействительная сессия → закрытие рукопожатия (403) или код `4401` |

Поля: `type` — тип главы (см. ниже; нет поля = `chapter`); `fmt` — `"mtx"` или `"mpx"`; `size` — размер файла в байтах (вместе с `id` определяет имя локального файла,
замена главы на сервере = другой `size` = перекачивание); `created` — unix-секунды.

Страницы сайта, на которые ссылается приложение: `/tos`, `/privacy` (настройки → «О приложении»).

### Вход через Telegram
1. `POST /api/auth/start` → `{token, url}`.
2. Клиент открывает `url` (`https://t.me/<бот>?start=<token>`), пользователь нажимает Start.
3. Клиент раз в ~2 с вызывает `GET /api/auth/poll/{token}` до `ok` (или `410`/таймаут ~10 мин).
4. Сохраняет `session` и `name`; дальше `Authorization: Bearer <session>` для REST и `?token=` для WebSocket.

## Типы глав и коды файлов

| `type` | Файл | `number` | Место в томе |
|---|---|---|---|
| `prologue` — пролог | `R01-P.mtx` | 0 (по одному на том) | первым |
| `chapter` — глава | `R01-03.mtx` | от 1 | дальше по номерам |
| `epilogue` — эпилог | `R01-E.mtx` | 0 (по одному на том) | после глав |
| `extra` — дополнительные главы вне сюжета | `R01-A01.mtx` | от 1 | в конце |

Код: `R`/`M` (ранобэ/манга) + номер тома (2 цифры) + `-P` / `-<NN>` / `-E` / `-A<NN>`; он же имя файла при скачивании (`Content-Disposition`)
и поле `code` манифеста. Уникальность главы — `(том, type, number)`. Клиент старой версии, не знающий `type`, покажет пролог как «Глава 0».

## Push-уведомления о новых главах (Firebase Cloud Messaging)

Необязательный канал: приложение подписывается на тему FCM `new_chapters` (имя совпадает с `FCM_TOPIC` на сервере и `Push.TOPIC` в приложении).
При публикации **новой** главы (замена существующей не считается) сервер шлёт в тему data-сообщение с высоким приоритетом:

```json
{"type": "chapter", "chapter_id": "12", "kind": "ranobe", "volume": "1", "number": "3", "title": "…", "created": "1792712832", "chapter_type": "chapter"}
```
(все значения — строки, так требует FCM). Тип `test` (`title`, `body`) — проверочное уведомление (`python -m server.push`).
Уведомление рисует приложение, учитывая настройку «Новые главы». Без Firebase приложение проверяет `GET /api/latest` по расписанию.

## Форматы глав

Оба формата — обычные ZIP-архивы с `manifest.json` в корне.

### `.mtx` (ранобэ)
```
manifest.json
0001.txt, 0002.txt, …     текст главы, разрезанный на части по размеру (по границам строк)
images/0001.jpg, …        иллюстрации (необязательны)
```
`manifest.json`: `format:"mtx"`, `version`, `title`, `volume`, `chapter`, `type`, `code`, `author`, `lang`, `chars`, `parts` (имена файлов с текстом по порядку),
`images` (иллюстрации, нумерация с 1; **список может быть пустым**), `part_bytes`, `created`.

**Версия `.mtx` — всегда 3**: и для глав с иллюстрациями, и для глав просто с текстом (тогда `images` пуст, папки `images/` нет).
Старые файлы версий 1 и 2 читаются как раньше (см. ниже).

* Склейка всех частей по порядку — исходный текст дословно (части режутся по строкам; слишком длинная строка — по пробелу/символу).
* Иллюстрация в тексте — **отдельная строка** `![подпись](img:N)`, где `N` — номер в `images` (с 1). Подпись может быть пустой.
* Версия 1 (старая): весь текст в одном `content.txt`, поля `parts` нет. Версия 2 (старая): части `0001.txt`… без иллюстраций, поля `images` нет.
* Версия файла выше известной клиенту → клиент показывает «обновите приложение», а не пытается читать.

### `.mpx` (манга)
```
manifest.json
pages/0001.jpg|png|webp, …
```
`manifest.json`: `format:"mpx"`, `version:1`, `title`, `volume`, `chapter`, `type`, `code`, `direction` (`rtl` \| `ltr` \| `vertical`), `pages` (по порядку), `created`.

Реализация чтения на Kotlin: `app/src/main/java/org/dedussamosval/alya/formats/` (без зависимостей, тесты — `app/src/test`,
фикстуры сделаны Python-кодом сервера).
